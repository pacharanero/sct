# Security policy

The named maintainer for `sct` is Marcus Baw. As part of Foundation onboarding, this project adopts the [Open Health Technology Foundation security-reporting process](https://openhealthtechnology.org/community/security/), including while its repository remains under `pacharanero`.

## Report privately

Do not report suspected vulnerabilities in public issues or pull requests. Email **security@openhealthtechnology.org**, naming `sct`, or use GitHub's private vulnerability reporting if it is enabled on this repository. Enabling and checking that GitHub route is a remaining onboarding task; email is the published reporting route.

Include the affected versions or commits, likely impact, safe reproduction steps and any suggested mitigation. Remove credentials, patient-identifiable information and licensed terminology content that cannot be shared. Use synthetic examples wherever possible.

If an issue could affect clinical results, clinical workflow or patient data, state that explicitly so it can also be considered as a potential clinical safety hazard. Security reporting is not a substitute for deployment-specific clinical safety assurance.

Disclosure is coordinated with the maintainer and Foundation. Refer to the Foundation policy for its response targets. No long-term support window for older `sct` versions is promised here; report the affected version even if it is not the latest release.
