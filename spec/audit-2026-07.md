# Code audit - July 2026

Full-codebase audits from 2026-07-17 and 2026-07-25 covering security, stability, and error-handling. This file preserves the historical identifiers, evidence, and checked-and-found-safe lists so the same ground is not re-audited from scratch. Remaining work is tracked in [`roadmap.md`](roadmap.md).

The 2026-07-17 audit found no high-severity issues: 3 medium, 4 low.

## Findings (evidence)

### R70 - `open_db_readonly` creates a stray DB on mistyped `--db` (Medium) - fixed

`src/commands/mod.rs:55-56` uses `Connection::open(path)`, which defaults to `SQLITE_OPEN_READ_WRITE | SQLITE_OPEN_CREATE`. `src/paths.rs:340-347` deliberately skips existence-checking the explicit `--db` path ("the caller's open() will produce a clearer error") - but with CREATE flags, open() *succeeds* on a typo, creating a zero-byte file, and the user instead gets "no such table: concepts" plus a stray junk file. `PRAGMA query_only = ON` (mod.rs:66) protects content after open, not creation. Every read command routes through this helper (lookup, ecl, codelist, refset, mcp, serve, size). `src/commands/tui.rs:42-45` and `src/commands/gui.rs:456-459` already open with `OpenFlags::SQLITE_OPEN_READ_ONLY`.

**Resolution:** `open_db_readonly` now uses `Connection::open_with_flags(path, SQLITE_OPEN_READ_ONLY | SQLITE_OPEN_NO_MUTEX)`, retaining `PRAGMA query_only` as defence in depth. Unit tests verify that a missing path is not created and that writes fail against an existing DB.

### R71 - TRUD `archiveFileName` joined into paths unsanitised (Medium) - fixed

`src/commands/trud.rs:501` (`releases_dir.join(&release.archive_file_name)`), `trud.rs:534` (`.tmp` variant), `trud.rs:757` (second copy). `archive_file_name` is deserialized from the TRUD API response (trud.rs:228); a value like `../../.profile` traverses out of `releases_dir` - an arbitrary-file-write primitive for a compromised/MITM'd API (HTTPS is the only mitigation). Inconsistent with the zip extraction path, which guards traversal.

**Resolution:** `TrudRelease` now validates `archiveFileName` during deserialization and accepts only one normal path component, explicitly rejecting both `/` and `\` so behaviour is safe on Unix and Windows. This fails closed for every consumer (`list`, `check`, and both download paths). Unit tests cover empty, dot, parent, Unix-separator, and Windows-separator names; a wiremock binary-level test verifies `../../escape.zip` is rejected and cannot escape the output directory.

### R72 - `sct serve` `$expand` pagination hardening (Medium) - fixed

The initial finding overstated the exposure: both expansion operations already capped `count` at 1000 before materialising responses. However, pagination parsing silently replaced malformed or negative values with defaults, the FHIR response could report the uncapped requested count rather than the effective count, and in-memory expansion used unchecked `offset + count` arithmetic. The routes had no integration coverage for these behaviours.

**Resolution:** pagination is now parsed and validated centrally for direct and batch `$expand` routes. Malformed and negative values return an HTTP 400 OperationOutcome, `count` is capped at 1000 before dispatch so the response reports the effective count, offsets beyond SQLite's signed-integer range are rejected, and page-end arithmetic is saturating. Valid offsets remain intentionally uncapped because arbitrary offset limits would break legitimate paging. Operation-level count caps remain as defence in depth; unit and live HTTP tests cover direct-by-id, direct-by-URL, and batch expansion paths.

### R73 - No request timeout; batch Bundle entries unbounded (Low) - fixed

Router at `serve/mod.rs:243-262` has no timeout/limit layers. Batch handler (`mod.rs:547-590`) takes `body: String` (axum's default 2 MB body limit applies) but iterates `bundle["entry"]` unbounded at mod.rs:568, sequentially, on one pooled connection inside a single `spawn_blocking`. Tens of thousands of tiny entries fit in 2 MB. Mitigated by the 127.0.0.1 default bind (mod.rs:52).

**Resolution:** router middleware now returns an HTTP 408 FHIR OperationOutcome when a request exceeds 30 seconds, and batch or transaction Bundles with more than 100 entries are rejected with HTTP 400 before borrowing a database connection. A live HTTP regression test verifies the entry cap. The timeout bounds client response time; as with Tower's timeout layer, already-running `spawn_blocking` work cannot be forcibly cancelled by Tokio and may finish in the background.

### R74 - Download temp-file leak + concurrent-run race (Low) - fixed

`trud.rs:534, 575-596` (second copy at 750-806). Good: checksum-mismatch path cleans up (remove before bail, ~607), and the rename (619/826) is same-directory so atomic. Bad: any read/write/flush error or Ctrl-C leaves `{name}.tmp`; two concurrent downloads share the same tmp path, so process B's still-open handle keeps writing to the inode after process A validates and renames it - corrupting the final file *after* A's SHA-256 check passed.

**Resolution:** both download paths now use `NamedTempFile::new_in` in the destination directory, so each invocation receives a unique temporary filename, all failure paths clean up via RAII, and `persist` atomically replaces the final file only after checksum verification. The existing wiremock checksum-mismatch regression now also proves the output directory is left empty.

### R75 - Corrupt DB treated as "no crossmaps"; exit 0 with empty mapping columns (Low) - fixed

`src/commands/codelist.rs:2458-2466`: `table_exists` returns `query_row(...).is_ok()` - I/O or corruption errors are indistinguishable from "table absent"; same for `column_exists` (codelist.rs:2467-2480) and the copies in `src/commands/transcode.rs:211-236` (plus `pt()` at transcode.rs:200-209 mapping SQL errors to `None`). At codelist.rs:2358-2359 this downgrades a broken DB to a stderr warning while emitting a CSV with empty Read2/CTV3 columns, exit 0 - a data-quality hazard for clinical codelists. `src/commands/read2.rs:456-475` does it correctly with `Result<bool>`. Same pattern, lower stakes: `get_subtree_size` (mod.rs:74-81) swallows its sqlite_master probe error with `unwrap_or(false)`.

**Resolution:** codelist and transcode schema probes now return `Result<bool>` and propagate SQLite errors exactly as the read2 importer does; transcode preferred-term lookups now preserve database errors too. `get_subtree_size` likewise propagates a failed transitive-closure probe rather than silently selecting the recursive fallback. A damaged database now fails the command instead of producing plausible but incomplete output.

### R76 - FST reader panics on truncated index (Low) - fixed

`src/index/query.rs:344-360`: `preferred_term` checks `idx.len() < 4`, then reads `count` from the file and slices `entries[mid * ENTRY..mid * ENTRY + ENTRY]` without verifying `4 + count*16 <= idx.len()`. A truncated/corrupt `snomed.fst` with valid magic/version (checked at `src/index/format.rs:138-152`) panics with an out-of-bounds slice. Reachable from user-supplied `--fst` in `sct sayt` / `sct serve /autocomplete` (panic kills that request task).

**Resolution:** `Index::open` now validates the terms-index entry count against its section length and checks every preferred-term text offset and length against the text section before accepting the mmap. Lookup can therefore slice trusted ranges without panicking. Regression tests mutate otherwise-valid index files to carry an oversized entry count and an out-of-bounds text range, and verify open fails cleanly.

## Follow-up audit - 2026-07-25

The follow-up review recorded `R39`-`R47`. Eight findings are resolved; the bounded/cancellable ECL portion of `R44` remains active as roadmap item `R53`.

- **R39 - mmap terms-index bounds (High): already fixed.** The earlier `R76` fix validates the entry count and every preferred-term offset/length when opening an FST, so later slicing operates only on validated ranges.
- **R40 - stack-unsafe ECL input (High): fixed.** Parenthesised expressions and attribute groups are capped at 200 levels; associative chains are bounded and balanced; repeated `MINUS` chains are bounded. Pathological input now returns a parse error instead of aborting.
- **R41 - TRUD API key in transport errors (Medium): fixed.** Generic transport errors from release probes and fetches pass through `redact_key()` before formatting, while HTTP-status messages remain key-free.
- **R42 - unbounded or malformed MCP Content-Length framing (Medium): fixed.** The official-SDK migration replaced non-standard Content-Length framing with newline-delimited stdio while retaining a 16 MiB bounded, cancellation-safe reader and explicit malformed-envelope errors.
- **R43 - Read2 zip-bomb memory growth (Medium): fixed.** `read_zip_entry_capped()` rejects entries above 512 MiB by declared size and bounds the actual decompressed read as defence against false size metadata.
- **R44 - remotely exposed expensive ECL expansion (Low): partially fixed.** Non-loopback `sct serve` binds now print a prominent no-auth/expensive-query warning. Full-result compound ECL materialisation and uncancellable blocking work remain open under roadmap item `R53`.
- **R45 - TRUD download durability before rename (Low): fixed.** Downloads call `sync_all()` after checksum verification and before atomically persisting the destination.
- **R46 - silent malformed MCP JSON (Low): fixed.** The bounded MCP adapter returns JSON-RPC parse/invalid-request errors; process tests cover malformed JSON and envelopes, invalid IDs, notifications, EOF, oversized input, and unterminated input.
- **R47 - TRUD `--api-key` process/history exposure (Low): fixed.** Every use emits a key-free warning directing users to `sct trud auth`, `--api-key-file`, or `TRUD_API_KEY`; the safer alternatives are documented.

The follow-up review also rechecked SQL parameter binding, FTS bound parameters, zip path traversal, TRUD SHA-256 verification, hierarchy cycle safety, varint bounds, the `unsafe` census, loopback defaults, and the committed lockfile without finding another issue.

## Checked and found safe (2026-07-17)

Recorded so future audits don't re-cover this ground from scratch:

- **SQL injection: none found.** All user values are bound parameters. The `format!` SQL sites interpolate only compile-time constants: `PRAGMA table_info({table})` is always called with the literal `"crossmaps"` (all 5 call sites verified); the serve CTE strings (serve/ops.rs:436-479) and `ALTER TABLE` column names (sqlite.rs:415-433) are static; `PRAGMA cache_size = -{kib}` interpolates a `u32`. `refset compare`'s `EXISTS`/`NOT EXISTS` is a fixed keyword from an enum.
- **Zip-slip: protected.** `extract_zip` (ndjson.rs:297-334) uses `entry.enclosed_name()` and skips unsafe entries; read2.rs:228-270 reads zip entries in memory only.
- **TRUD API key: not leaked.** Key-bearing URLs (trud.rs:1015/1037) are never printed. Verified in the vendored ureq 3.3.0 source (error.rs:229-268) that no error Display variant includes the request URL except `BadUri`, which only fires for missing scheme/host - impossible here (hardcoded `https://` base). All `{e}` formattings in trud.rs are therefore safe.
- **Bind addresses:** `sct serve` defaults to 127.0.0.1 (serve/mod.rs:52); `sct gui` is hardcoded to 127.0.0.1 (gui.rs:110-115). No CORS layer - the safe default for a localhost API. All serve endpoints are read-only; the pool uses `open_db_readonly` with `query_only=ON`.
- **Non-ASCII panics:** the ECL lexer indexes a `Vec<char>` (ecl/lex.rs:111,123); byte-slicing in format.rs:163-215 and index/normalise.rs:52-64 derives offsets from `find`/`rfind` of ASCII needles, so stays on char boundaries. Heavy `unwrap()` counts in trud.rs/markdown.rs are static `ProgressStyle` templates, `writeln!` into `String`, and test code.
- **`sct size`'s read-write `Connection::open` (size.rs:428)** is intentional: TCT build after an explicit interactive prompt.
