# Data and Syntax Boundaries

Display text, identifiers and metadata are data, even when read from a locally built database. JSON and YAML can carry embedded newlines and delimiter characters. Successfully parsing a source artifact does not make its fields safe to interpolate into another language.

## Contract

- Preserve original values in canonical NDJSON, JSON/YAML responses, SQLite, Arrow and Parquet. Use their serializers or bound parameters, not handwritten quoting.
- Before emitting a string SCTID into an identifier stream, filename, graph identifier or implicit ECL operand, call `sctid::validate_syntax`. This requires nonempty ASCII digits, independently of optional checksum policy. Do not strip a numeric prefix from malformed input. Do not apply this SNOMED-only rule to external terminology codes.
- For human single-line fields and unquoted TSV values, use `format::single_line`. It replaces controls and non-space whitespace with spaces. Apply it to substituted values, not a user-supplied template: template separators remain intentional syntax.
- For Markdown data in headings, prose and table cells, use `text::markdown_text`. This is not an encoder for code spans, HTML attributes, JavaScript or shell strings.
- CSV quoting must cover every field, including codes and headers, and both CR and LF. A quoted CSV cell still needs a separate contract for a delimiter-separated list inside it. Reject unrepresentable internal delimiters instead of turning one code into several.
- Dynamic GUI IDs must be carried as escaped attribute data and read by event listeners. Never embed data in JavaScript source, including inline event handlers. HTML escaping alone does not protect a JavaScript string inside an attribute.
- Shell instructions containing user paths require shell-specific literal quoting. Rust subprocess invocation uses explicit argv, not an interpolated shell command.

## Codelist Persistence

All writers, including CLI mutations, imports, composition, MCP tools and SDK callers, go through `render_codelist` before atomic persistence. Each body line must contain no control characters, carry a structurally numeric SCTID where applicable, and parse back into the same `ConceptLine` value. Unrepresentable terms, comments or identifiers are rejected; they are never silently rewritten into a different member set. YAML front-matter remains serialized normally and can retain multiline descriptions.

This also rejects a term containing the body language's inline-comment separator when it would be parsed as a comment, and rejects a `Comment` value that would actually be read as an active or excluded member. Errors occur before creating or replacing the destination file. Existing unsafe data is not silently repaired.

## Command Audit

| Surface | Boundary protection |
|---|---|
| `codelist` and its aliases; MCP codelist mutations; SDK codelist writes | Shared render/parse validation and atomic writes; field-aware CSV and Markdown exports |
| `lexical`, `semantic`, `lookup`, `refset`, `proximal-primitives` | Single-line display fields; string identifier streams validated before result output; structured serializers unchanged |
| `fst`, `sayt` | Numeric FST identifiers; single-line selection/label text; SAYT stdio uses JSON serialization |
| `map` / `transcode` / `crosswalk` | CSV quoting and single-line TSV/text values; equivalents cells reject their internal delimiter in a code; JSON arrays preserve literal codes |
| `ecl` | Numeric expression output; compression consumes whole annotations as annotations, never as additional IDs |
| `serve` | JSON serialization; `isa/` and `refset/` implicit URL slots validate a single identifier, while explicit `ecl/` remains an expression |
| `diagram` | Validate root and referenced graph identifiers before rendering; DOT/Mermaid-specific label encoding and single-line tree labels |
| `markdown` | Validate identifiers before deriving filenames; Markdown plain-text encoding for display fields; refuse nonempty destinations before reading input to prevent mixed-release exports |
| `gui` | JSON API, escaped HTML text/attributes, DOM event listeners, D3 text methods |
| `bench` | Serialized structured reports; context-specific human, Markdown and HTML output |
| `info`, provenance | Single-line human metadata, lossless structured metadata |
| `dmwb` | Single-line table/dump fields; bound SQL for data storage |
| `ndjson`, `sqlite`, `parquet`, `embed`, `read2`, `tct` | Structured artifact writers and bound SQL; no new handwritten record syntax |
| `mcp` non-codelist tools | JSON tool results and serialized transport framing |
| `trud` | TOML value serialization followed by reparsing/value verification for credential writes; normal archive path checks |
| `completions` | Scripts generated by clap; shell-specific quoting for installation hints |
| `diff`, `history`, `size`, `paths`, `tui` | Structured serializers where provided; human diagnostics/UI are not codelist or identifier-stream serializers |

This is a data-to-syntax audit, not a claim that all inputs are trustworthy or that every display format is a lossless interchange format. Arbitrary user templates are intentional formatting programs. Spreadsheet formula interpretation, third-party Markdown extensions, deployment environment configuration, and malicious existing filesystem symlinks are separate boundaries, not solved by CSV quoting or single-line display encoding.

## Regression Evidence

`tests/codelist-boundaries.rs`, `tests/line-output-boundaries.rs`, `tests/ecl-input-boundaries.rs` and `tests/output-boundaries.rs` exercise synthetic RF2 -> canonical NDJSON -> real SQLite workflows, then introduce adversarial values at the relevant boundary. Assertions cover exact membership, record counts, refusal before file replacement, and preservation of original structured values. Core codelist, MCP, format, provenance and benchmark unit tests cover their shared helpers.

`tests/gui-boundaries.js` is a browser regression harness using the complete current GUI and mocked local APIs. It clicks parent, attribute, children-list and loaded-child controls, checking literal navigation and lack of injected execution. Its header documents execution through Playwright MCP; it is not currently part of the Cargo/CI gate. Rust tests additionally reject reintroduction of data-bearing inline handlers.

New command implementations must identify their output contexts and add an adversarial-value test for any new encoder or syntax boundary. A safe parser for one format is not a sanitizer for another.
